# Submission checklist

## Required artifacts

- [ ] Public GitHub repository
- [ ] Working demo or recorded demo
- [ ] Explicit CMC endpoint list
- [ ] Real API call code and a limited redacted response
- [ ] API friction note
- [ ] Selected track: Real World Assets
- [ ] X post linking submission and demo video with `#BuildwithCMC`
- [ ] Demo video uploaded and linked in the DoraHacks form

## Before submission

- [ ] Verify the event key's actual entitlement and endpoint behavior.
- [ ] Verify the core works with documented Basic access.
- [ ] Verify route terms against current primary sources.
- [ ] Verify quote provider coverage and display permissions.
- [ ] Confirm data attribution and evidence-retention posture.
- [ ] Remove any secret, private wallet data or real user data.
- [ ] Run frontend build, backend tests and a fresh-browser demo.

## Evidence policy

Keep only the minimum real response needed to demonstrate the working integration. Label captured-at times. Never present a synthetic fixture as a live response. Never publish a complete unrestricted CMC dataset.

## Demo script

1. Friday after the U.S. close, holder needs USDC before a stated deadline.
2. Create the plan with an exact instrument and quantity.
3. Watch the plan across recorded observations and a session change.
4. Switch destination to brokerage shares and show xPort's distinct prerequisites.
5. Inspect the CMC identity join, route source and quote evidence.
6. Show a provider failure producing an honest partial state.
